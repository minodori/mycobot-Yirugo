## 1. 무엇이 바뀌었나

### 1.1 사이클 — armed pose를 걷어내고 통을 대기 자세로 (BSC)

`ARMED_POSE_HANDOFF.md` 1.5절이 사슬로 재면서 드러난 것: armed pose는 팔을 뒤로
접은 자세이고 정렬 위치는 베드 앞이라, 목표마다 접었다 펴는 **우회**였다.
통 자세를 대기 자세로 쓰면 그 우회가 사라진다.

| 사이클 | 대기 자세 | 통에 놓나 | 정렬 이동량 중앙 | 복귀 합 |
|---|---|---|---|---|
| LPC | look pose | 아니오 | 509° | 7753° |
| ASC | armed pose | 아니오 | 461° | 7465° |
| **BSC** | **통 자세** | **예** | **362°** | **6247°** |

(같은 세션, 반복 10회. 사슬로는 A → D **−28.8%**.)

통 자세는 `scripts/find_bin_pose.py`로 뽑았다 —
`[+122.49, +15.91, −85.05, −27.30, −0.96, −4.23]`도.
**통 위치(g_base (0, +0.15), 림 z=0.100)에 묶여 있고 왼쪽 전용이다.**

### 1.2 안전·운용

- **YOLO가 팔을 직접 안 움직인다**(`publish_target_point` 기본 false).
  파지 명령은 `harvest_sequence_node`만 낸다. 2026-07-24 자동 루프 사고의 통로를
  구조적으로 닫은 것이다.
- **수확 중 검출을 얼린다**(`set_judgment_enabled`). 해제는 "지금부터 다시 봐라"로
  동작한다 — look pose에 서 있으면 그 자리에서 다시 누적한다.
- **복귀 실패 = 시퀀스 정지.** 실물에서 이걸 안 막아 사고가 났다(3절).
- **목표마다 그 목표의 반지름을 먼저 발행**한다. 예전엔 YOLO가 최적 목표 하나에
  대해서만 내서, 2번째 이후 목표는 남의 반지름으로 그리퍼를 열고 있었다.

### 1.3 목표 출처 — YOLO / 보정본 파일

`target_source: yolo | file`. 파일은 `export_detections.py` 출력 형식 그대로이고
좌표가 g_base라 TF를 안 탄다. `--compare`로 보정 전후 차이를 mm로 확인한다.

```bash
# 한 줄로 전부(스택·YOLO·좌표변환·시퀀스·RViz·제어판)
ros2 launch mycobot_280_pick pick_pipeline.launch.py cycle:=bsc

ros2 launch mycobot_280_pick pick_pipeline.launch.py \
    cycle:=bsc target_source:=file targets_file:=bags/today_fixed.json

# 수확 시작(YOLO가 직접 안 움직인다)
ros2 service call /start_harvest_sequence std_srvs/srv/Trigger
```

```bash

```

## 3. 첫 실물 시험에서 나온 것 (2026-08-03) — **여기서 이어서 하면 된다**

목표 2개로 돌렸다. **첫 목표는 5단계 전부 성공**(정렬·그리퍼·직진·파지·후퇴).
그 뒤가 갈렸다.

### 3.1 그리퍼 끝단이 목표보다 +30mm 더 들어간다 ← **다음 할 일 1번**

`flange 목표 = 열매 − 접근축 × GRIPPER_LENGTH_OFFSET_M(0.09)`이므로, 30mm 초과면
**실제 flange→끝단이 약 0.12m**라는 뜻이다. 그 상수 주석은 `0.09 # 실측`뿐이라
언제 어떻게 쟀는지 근거가 없다.

- **할 일**: 자로 flange 면에서 손가락 끝까지 재고 상수를 고칠 것.
- YOLO 깊이 오차(열매를 **더 가깝게** 잡는 방향)는 부호가 반대라 주범이 아니다.
- 고치면 `APPROACH_STANDOFF_M`·`MIN_ALIGN_RADIUS_M`과의 관계도 같이 확인할 것
  (그 상수 주석에 결합이 적혀 있다).

### 3.2 긴 전이가 전부 실패했다 ← **대응은 있으나 실물 재확인 필요**

```
Motion plan was found but it seems to be invalid (possibly due to postprocessing).
```

실물 카메라가 octomap을 계속 갱신해, 계획 직후 씬이 바뀌어 재검증에서 충돌로
잡힌다. 짧은 구간(정렬·직진)은 `/clear_octomap` 직후라 통과했고 **긴 전이
(통 자세 경유·복귀·look pose)만 골라 실패**했다.

- **대응**: `look_pose_gate:=true` — 팔이 look pose에 있을 때만 클라우드를 낸다.
  **이번 시험에서는 켜지 않은 채 돌렸다.** 다음엔 켜고 시작할 것.
- 게이트를 켜도 octomap voxel은 목표마다 지워져 수확 중 비어 있다. voxel까지
  고정하려면 clear를 시퀀스 단위로 바꿔야 하는데 **그건 장애물 회피를 켜는
  결정**이다(핸드오프 5절: 성공률 100 → 77%). 미결.

### 3.3 복귀 실패 후 다음 목표로 진행하며 베드와 충돌 ← **고침**

경고만 하고 넘어가서, **열매를 쥔 채** 베드를 가로질러 이웃 토마토를 쳤다.
이웃 열매는 장애물이 아니다(함정 17).

- **고쳤다**: 복귀 실패를 실패로 보고하고(`coord_to_goal_node`), 시퀀스가 남은
  큐를 버리고 멈춘다(`harvest_sequence_node`). **실물에서 아직 재확인 안 됨.**

## 4. 이 세션에서 밟은 함정 (같은 자리에서 다시 헤매지 않게)

| 무엇 | 증상 | 원인 |
|---|---|---|
| **런치 중복** | 팔이 안 움직이고 **그리퍼만** 움직였다 | `coord_to_goal_node` 2개가 같은 컨트롤러에 서로 다른 궤적을 밀어넣어 서로 취소. `move_group`·`ros2_control`도 2벌이었다 |
| **리포커스 전 자세 불일치** | 리포커스하면 팔이 엉뚱한 자세(통 자세)로 감 | `refocus_servos`는 실물 현재 각도로 잠그지만, relay 재개 순간 **시뮬 자세**로 간다. **리포커스 전에 시뮬을 실물에 맞춰야 한다** |
| **판단 얼림이 남음** | `export_detections.py`가 60초 기다리다 빈손 | `emergency_stop`으로 멈추면 판단 해제가 안 불린다. 지금은 해제가 look pose에서 즉시 재누적하게 고쳤다 |
| **줄임표 명령** | 빈 씬에서 조용히 100% 성공 | 문서가 `--cycle asc ...`로 줄여 적었다(함정 18). 런북은 명령을 전부 적는다 |
| **RViz 설정 누락** | 제어판 큐브가 안 보임 → 보이는데 메뉴가 안 열림 | 디스플레이(InteractiveMarkers)와 **Interact 도구**가 설정에 없었다. 넷 다 넣었다 |
| **속도 배수가 안 먹음** | x5로 해도 차이 없음 | 접근·후퇴에만 걸려 있었다. 긴 구간(경유·정렬·복귀)에도 걸도록 고침 |

## 6. 사실관계 정정 (문서에 잘못 적혀 있던 것)

- **`sync_plan`은 단방향이 아니다.** 런북 5절에 "계획 → 실물 단방향"이라고
  적었는데, 실제로는 `/joint_states`를 **되돌려 발행**한다(`control_sync_plan`이
  퍼블리셔로 잡힌다). 실물 관절각을 ROS로 가져오는 경로가 이미 있다는 뜻이라,
  "손 티칭은 불가능"이라던 판단도 다시 봐야 한다.
- **핸드오프 1.5절의 "armed 33.3cm vs 통 27.7cm"는 두 잣대를 섞은 값**이다.
  같은 도구로 한 세션에서 재면 통 28.4 / armed 27.0 / look 29.9cm다(10.3절).
